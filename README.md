# 程式炸彈拆除專家：最後倒數（Defuse a Bomb）

**v1.4.0 · 繁體中文 · 國中程式設計 · 1～3 位學生合作教育遊戲**

正式網站：https://defuse-a-bomb.onrender.com

GitHub：https://github.com/Chuang-Chih-Hao/Defuse-a-bomb

本遊戲的數位炸彈、線路和裝置皆為虛構電腦安全謎題，不涉及現實爆裂物或電路拆解。

## 1. 適用課程與目標

- 適用：1～3 位具 Scratch 入門經驗的學生與老師；不依年級分配難度，教師可依學習進度調整。
- 教學形式：40 分鐘上課、10 分鐘休息、40 分鐘上課，老師可在中間暫停倒數。
- 學習：**Sequence 執行順序**、**if/elif/else 條件判斷**、**for 迴圈**、**Debug**、**變數與運算**、**清單索引**、**自訂函式**。
- 操作工具：**Scratch 風格視覺積木 + 旁邊的唯讀 Python 對照**。修改積木會即時更新 Python 字串，不執行學生輸入的任意 Python/JavaScript。
- 與 Scratch 類似：藍色動作積木、紫色 C 形「如果／否則」積木、橘色 C 形重複積木、事件帽型積木；可調參數、重新排序與實際執行驗證。

## 2. 教師房間：1～3 位學生都能玩

老師仍然需要建立房間，持有私密教師憑證並保留**開始／暫停／恢復／指定關卡／重試／難度設定／重置**等管理功能。**不需要剛好兩位學生在線才能開始**，但至少需要一位學生在線，且最多三位學生加入。

| 實際連線人數 | 合作角色 | 教師可以做的事 |
|---|---|---|
| 老師 + 1 位學生 | 老師補足第二個角色，兩人一人分析、一人操作，每關交換 | 兼任當前角色，並繼續使用教師控制台 |
| 老師 + 2 位學生 | 兩位學生分別分析、操作，每關互換；老師監控 | 控制台照常使用，不會替學生核准或執行 |
| 老師 + 3 位學生 | 每關有分析員、操作員及情報支援員，三位學生按關卡輪流換位 | 控制台照常使用；支援員只能觀察與作戰通訊，不能修改或核准 |

教師與學生皆透過獨立憑證驗證。學生**不能**使用教師控制台；情報支援員不能偷偷接管當前操作員或分析員的專屬權限。

### 正常加入流程

1. 老師按 **教師 · 建立專屬房間**，取得六碼代碼。
2. 學生在不同裝置輸入相同房間代碼及暱稱加入。
3. **至少 1 位學生在線**，老師即可按 **開始任務**。
4. 分析員讀取機密題目並向操作員說明，操作員修改 Scratch 積木；分析員核准後，操作員執行。
5. 三位學生時，情報支援員透過作戰通訊提供建議，下一關自動輪換。後加入的學生先觀察，**下一回合**再加入角色輪換，避免打斷正在執行的程序。
6. 老師可在任務完成後選下一關、指定關卡、重試或進入挑戰實驗室。重新整理網頁能在房間仍存在的情況下使用原有憑證重連。

**角色輪換示例（3 名學生）：** 第一關 A 分析、B 操作、C 支援；第二關 B 分析、C 操作、A 支援；第三關 C 分析、A 操作、B 支援。

**老師與一名學生時：** 第一關老師分析、學生操作；第二關學生分析、老師操作；後續持續交換。不會把同一位學生要求同時核准與執行。

## 新版遊戲流程：題目、作答、解除

學生畫面將 **本關題目** 與 **Scratch 程式積木** 擺在優先位置。操作員詢問分析員的題目規則，修改積木；分析員按「✓ 核准答案」，操作員按「▶ 解除核心」，成功後老師繼續下一關。遊戲仍保留 Python 3 對照，但把隊伍資料、Watch Window 與進階除錯收進可展開區域。

- 題目顯示在畫面主要位置；教師與分析員看到完整目標，操作員只看作答提示，不會得到機密答案。
- 秒數、穩定度與解除結果改為精簡狀態區。減少大面積裝置動畫、重複資訊及次要欄位。
- 手機版優先顯示題目、回答積木、解除按鈕，**Python 程式仍在積木下方可見**。
- 需要協作時可使用「合作訊息」；完整隊伍名單與變數監視器可自行展開。
- 教師保留原本完整開始／暫停／切換關卡／換題等控制權，學生仍支援 1～3 人彈性合作。

### 同類型題目不再反覆一模一樣

伺服器為每個房間的每一關、每種難度保留已出題版本。第一次提供示範題，同一房間再次按 **「同關換新題」**、重新指定已玩過的關卡，或重新開始該關時，會取用尚未出現的目標；題庫用完後才重新洗牌，且不會立刻重複上一題。

| 題型 | 會變化的實質解題目標 | 同難度題庫 |
|---|---|---|
| 線路順序 | 正確訊號排列與初始積木順序 | 24 種 |
| IF 密碼 | 顏色、能源比較門檻、AND／OR，進階含第二組條件 | 24 種 |
| for 迴圈 | 要執行的實際次數 | 9 種 |
| 綜合 Debug | 三段指令順序、顏色、條件門檻、迴圈目標 | 24 種 |
| 變數與運算 | A／B 槽、乘數、整除數、餘數以及初始化數值 | 24 組規則，初始值另隨機 |
| 清單索引 | 不同的兩個晶片位置與初始顏色排列 | 20 種位置配對 |
| 自訂函式 | 四個函式內積木的正確順序 | 24 種 |

出題和檢查都由伺服器完成，兩位學生會拿到同一份題目狀態，**操作員不會收到正確答案**。既有的「挑戰實驗室」由分析員自訂規則，為尊重學生所選題目，系統不會擅自改動已指定的自訂目標。

## 3. 七大主線關卡

| 關卡 | 學習重點 | Scratch 積木玩法 | Python 觀察 |
|---|---|---|---|
| ① 數位線路危機 | Sequence | 依分析員的正確訊號順序，用箭頭或拖曳重新排列動作積木 | activate("BLUE") |
| ② 邏輯密碼鎖 | IF / ELSE、AND / OR | 改顏色、能源門檻與布林運算；測試不同輸入 | if … and/or …: |
| ③ 無限倒數陷阱 | for 迴圈 | 調整起點、終點、步進；執行剛好的次數 | for i in range(start, stop, step): |
| ④ 駭客的最終程式 | Debug | 同時修正順序、條件式、迴圈 | Python 多段程式對照 |
| ⑤ 能量分配站 | 變數賦值、乘法、整除 `//`、餘數 `%` | A／B／C 槽初始數值每次生成，由分析員指揮設定 C | `C = (A * 2 // 1) % 5` |
| ⑥ 晶片陣列鎖 | 清單與索引 | 五色晶片、選擇兩個位置交換；可觀察 IndexError | `chips[0], chips[4] = chips[4], chips[0]` |
| ⑦ 緊急冷卻協議 | `def` 函式定義與呼叫 | 先排序四步函式內容，再用一個 `cool_down()` 呼叫；最多 6 個積木 | `def cool_down():`、`cool_down()` |

基礎模式使用較少步驟，進階模式增加模組、條件群組及迭代。執行後有動畫、可查看每次指令的執行追蹤；失敗後可修正再試。

**計分**：錯誤操作減 18 點穩定度、扣 15 秒、扣 35 分；每關兩次提示，提示扣 25 分。成功有分數與時間獎勵，失敗可請老師重試。

## 4. Python 3 轉譯、單步執行與監視器

遊戲右側為 **Python 3 對照（`defuse.py`）**，從有限積木結構即時產生，縮排採四個空白，涵蓋賦值、if/elif/else、for/range、清單交換與 def 函式。這是**教學用 Python 對照，不允許輸入／執行任意 Python**，避免任意程式碼執行風險。

- **滑鼠同步高亮**：滑鼠滑過 Scratch 積木，右側對應的 Python 行號亮起；滑過 Python 程式行，也能找到相應積木。
- **單步執行**：分析員按「核准」後，操作員按「單步執行」，伺服器一次執行一個已驗證積木／情境，並同步推送積木 id、Python 行號、Watch 快照與錯誤提示給房間內所有連線成員（老師及 1～3 位學生）。
- **Watch Window**：第五關可看到 A、B、C、source_value、temp；第六關即時看 chips；第七關觀察步驟數與主程式積木數。
- **錯誤停止**：單步遇到第一個失敗項立即停止並由伺服器扣除穩定度／時間，操作員必須修改積木重新經分析員核准。第六關輸入位置 6（合法 1～5）會出現白話的 IndexError。
- **執行安全**：伺服器對每個輸入欄位、整數範圍、排列及授權角色進行驗證，最多追蹤 32 步，並不啟動任何 Python 直譯器或 Javascript eval。

## 5. 自由選擇難度（不依年級）

| 模式 | 分析員資訊 | 操作員 | 額外限制 |
|---|---|---|---|
| 基礎模式 | 白話任務、規則及引導步驟 | 操作積木並觀察完整 Python | 重視順序與理解 |
| 進階模式 | **僅提供目標 Python 程式碼**；必須讀碼口頭說明 | 操作積木，須向分析員詢問 | 積木數量提示／上限 6；穩定度低於 60% 時，右側部分運算子顯示為 `???` |

**難度與年級無關**：同年級也可因程式基礎不同採用不同模式，老師可依課堂表現切換。雜訊只影響右側視覺顯示，不修改伺服器運算或積木資料。教師可在非執行狀態切換模式，然後重新開始關卡。

**教學節奏**：原本 80 分鐘課程可以優先進行前四關與實驗室；第五至七關可以安排下一堂課，或由教師依學生進度使用「指定關卡」操作。七關不強制壓縮到同一堂 80 分鐘內。

## 6. 第二節：挑戰實驗室

老師按 **挑戰實驗室**，會在設計者的畫面解鎖三種任務。**分析員設計，操作員解題**：

- **任務 1／訊號順序**：自訂三種不同顏色的正確順序。
- **任務 2／布林密碼**：自訂顏色、20～80 的門檻與 AND 或 OR。
- **任務 3／迴圈陷阱**：設定要執行 2～10 次的目標。

設計流程：選擇任務類型 → 填入參數 → 觀察 **發布前題目預覽** → 檢查規則 → 按 **確認預覽，發布給操作員**。

**重要修正（v1.1）**：OR 預覽與分析員正式任務卡一律顯示「或（OR：任一條件成立）」；AND 則顯示「且（AND：兩項都成立）」。例如：

> 顏色為黃色 YELLOW **或（OR）** 能源 > 80

不再出現「YELLOW 且能源 > 80；正確操作為 OR」的矛盾文案。

實驗室還會驗證：顏色不重複、門檻範圍合理、發布後才開啟倒數、發布中的題目不能重複覆蓋、老師暫停中的任務不能被新題覆蓋。**未發布的草稿選擇會保留**，不會因房間同步而重設；發布後會明確通知已發布、等待操作員修改。挑戰結束後可發布下一題，也可請老師按 **實驗室換手**，交換設計者與解題者。

## 7. 教師控制台

只有持有建立房間時產生的私密教師憑證才能操作控制台。可以：

- 開始遊戲、暫停／恢復倒數、選擇分鐘數、調整基礎／進階模式；
- 切換指定關卡、下一關、重試、重設整場；
- 開啟挑戰實驗室、交換設計角色；
- 查看每位學生線上狀態、修改／執行／失誤／提示次數、團隊分數、闖關結果與學習回饋。

已啟動的關卡不能直接改難度／分鐘數，須在下一回合生效；避免教學中未預期的時間改動。

## 9. 本機安裝

需要 Node.js 20+、npm：

~~~bash
git clone https://github.com/Chuang-Chih-Hao/Defuse-a-bomb.git
cd Defuse-a-bomb
npm install
npm run build
npm start
~~~

開啟 http://localhost:3000

| 指令／端點 | 說明 |
|---|---|
| npm run dev | Node.js watch 開發伺服器 |
| npm run check | 檢查伺服器與前端 JS 語法 |
| npm test | Node.js 單元測試、Socket.IO 多人整合測試 |
| npm run build | 執行語法檢查及測試（前端原生 HTML/CSS/JS 不需打包） |
| GET /health | 健康檢查 |
| GET /api/info | 專案版本、關卡名稱 |

額外 Chromium 真實三人瀏覽器測試：

~~~bash
npm install --no-save playwright@1.56.1
npx playwright install chromium
node tests/browser-smoke.js
node tests/room-sizes-browser.js
~~~

驗證正式 Render 網站時可設置環境變數 TARGET_URL=https://defuse-a-bomb.onrender.com；GitHub Actions 在每次 main 推送時會自動執行本地／正式站三人流程與 HTTP/WebSocket 檢查。詳見 [Game CI](https://github.com/Chuang-Chih-Hao/Defuse-a-bomb/actions)。

## 11. 安全、架構與限制

- 前端原生 HTML/CSS/JavaScript，伺服器 Node.js + Express + Socket.IO；教學用程式透過安全且受限的結構化指令模型執行，完全不 eval 任意 JavaScript / Python。
- 教師與最多三位學生各有獨立高熵 token；伺服器驗證角色、權限、核准版本與輸入規則。操作員不會收到機密正確答案。
- Python 對照為**唯讀教學示意**，不是自由文字 Python 執行環境。
- 單台 Node.js 記憶體存放房間；**Render 重啟、休眠或重新部署後房間會消失**。不支援多執行個體／持久化記錄。請上課前建立新房間，並使用 HTTPS。
- 測試為自動化模擬三個獨立瀏覽器環境，不等同真人使用不同裝置及完整 80 分鐘的課堂驗證。
